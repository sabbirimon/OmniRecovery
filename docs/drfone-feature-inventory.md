## Local observations

- The Mac Toolbox used a pale sidebar, white workspace, blue selection, pastel feature cards and colorful category icons. Observed symbols included a blue recovery clock, a pink key, a blue wrench, and a green chat tile. The nested device tree showed Samsung and Xiaomi entries. The Samsung page displayed model-specific USB debugging illustrations. Xiaomi appeared by model name. Its setup page and any device scan were not exercised.
- The bundle includes individual Mac apps for recovery, system repair, phone transfer, social-app restore, screen unlock, erasure, and password management. It contains the app icon and module ICNS files, raster category icons, Android helpers, and HTML/JavaScript report assets. The main x86-64 executable uses Mono and Xamarin.Mac managed assemblies. Module-connection headers expose the app-to-module interface. Proprietary recovery source was not present in the inspected bundle material.
- Live `vmmap` and stack samples measured about 145 MB of physical footprint at the observed point and about 284 MB peak. The live mappings included Xamarin.Mac, Android connection, device management, transfer, SQLite, and the shared module bridge. Stack samples showed Mono execution and runtime workers. These observations concern the Mac process during connection and navigation. They establish no recovery result or scan-memory benchmark.

The paid rows are reference workflows for independent OmniRecovery development. No vendor code, credentials, or artwork were imported into the project.
