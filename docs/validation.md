# Validation plan

Phase 0 defines the release acceptance criteria. The Android development slice has a narrower synthetic baseline. Future release test reports will identify the exact tool build, OS image, hardware and fixture digests.

## Development baseline

Eleven synthetic integration tests passed with Rust 1.99.1 on Intel macOS 15.8.2. They checked read-only source preservation at the byte level, exact JPEG/PNG bytes across scanner and sparse chunk boundaries, sparse checksum and malformed-input rejection, a 4.096 TB logical sparse gap without expansion, changed source/finding rejection, deterministic JSON, and pre/post image and logical export comparisons. The release binary also completed all four commands using independent synthetic fixtures under a macOS network-deny policy. Linux and Windows received compile checks. These tests cover parts of V01–V03 and V10. Physical write blocking, process isolation, case services and release controls have separate gates. A small fixture baseline does not measure field recovery rates.

Version 0.1.1 adds a storage label and bounded byte-range carving. The synthetic suite verifies whole-input hashing, absolute candidate offsets, clipped sparse gaps, rejection of candidates crossing the selected boundary and rejection of an out-of-bounds length.

Version 0.1.2 passed 16 synthetic Rust integration tests, including deterministic repair and encrypted archive creation. A separate integration check created an archive through the Rust CLI and read it using the Android companion's compiled Kotlin reader on the JVM. Both files matched exactly. A wrong passphrase and a tampered archive were rejected. Chrome rendered an actual CLI scan report and exercised the media filter. The Android debug APK signature and macOS disk image contents were verified. Android document-provider restore and Windows runtime tests remain open.

Desktop 0.2.0 passed the 16 engine tests and a macOS test that rejects same-physical-drive media output before reading or writing. The Universal DMG contained the verified Intel and Apple Silicon slices. The installed Intel Mac app ran the built-in scan, reported one PNG and one JPEG, and displayed the verified preview. Apple Silicon runtime tests and successful recovery onto a separate physical drive still need hardware validation.

Version 0.3.0 adds four synthetic tests covering category search, selected-file transfer, backup GPT provenance and scoped JSON-line requests. The same-drive rejection test still passes. The Android companion APK builds with the new launcher icon. Physical phone acquisition and destructive sanitization execution remain outside the release validation scope.

## Acceptance cases

| ID | Exercise | Acceptance |
| --- | --- | --- |
| V01 | Import a known-answer immutable raw image, then acquire sacrificial physical media on each qualified path | Source and persisted bytes have the expected SHA-256 and byte count for complete acquisitions. Independent measurement observes zero writes to source media. Record versions and topology |
| V02 | Use symlinks, hard links, reparse points, mounted volumes, same backing disk, shared storage layers, hot-swap and unknown ancestry | Acquisition rejects unsafe or unresolved combinations before reading evidence. Recovery writes only to the allowed case destination. Test each advertised host OS and hardware blocker path |
| V03 | Inject short reads, bad sectors, retry exhaustion, source mutation, full disk, interrupted flush, tampered chunks and process kills | Precise unreadable ranges and attributable status survive. Persisted objects verify independently. Unsafe resume fails closed. Crash recovery preserves committed work and detects incomplete staging. Nonce uniqueness holds through retries and restores |
| V04 | Mutate an event, remove or reorder records, fork a ledger, roll back the vault, rotate signers, restore backups and disconnect the witness | The verifier identifies broken history and stale or missing external anchors. Sensitive operations stop when current witness policy fails. Historic signatures remain verifiable under recorded policy |
| V05 | Attempt invalid role grants, cross-case and cross-tenant access, stale approvals, duplicate principals, grant replay and argument swaps | Unauthorized operations are denied before effect. Audit records identify authenticated actors and distinguish unauthenticated attempts. Exactly one durable authorization consumes a valid operation nonce. Recovery reconciles uncertain outcomes |
| V06 | Feed an agent prompt injection embedded in media or metadata, request extra fields, exploit unknown parameters, revoke grants mid-run and flood queues | Evidence instructions cannot change policy, jobs or output projection. Unauthorized fields never appear. Revocation and quotas apply across concurrent operations. Replay accepted plans without inference and compare canonical findings |
| V07 | Fuzz all parsers and IPC boundaries. Exercise archive bombs, malformed media, hostile plugins and local model packages | Worker timeout, memory limits, sandbox and read capabilities contain failures. No writes to source, arbitrary paths or unrelated cases. No reachable crash, hang or sandbox escape remains unresolved for the release scope |
| V08 | Probe network from services, workers and adapters. Try wrong TLS identities, wrong provider versions, stale revocation and log/dump canaries | Air-gap profile shows zero IP socket use in qualified workflows. Lab rejects untrusted identities and out-of-policy destinations. Strict provider never falls back. No secret or evidence canary appears in diagnostic outputs |
| V09 | Race holds against deletion, exercise retention and incomplete key disposal, and swap export device or recipient after approval | Hold blocks destruction through all storage paths. Export publishes only to the approved recipient and route. Report incomplete disposition where any required copy or proof is missing. Sanitize only sacrificial authorized targets during testing |
| V10 | Carve and parse known, negative and adversarial fixtures, including fragmented, reused, zeroed, encrypted and truncated data | Every recovered result has a byte-range explanation and validation state. Complete outputs match ground truth where it exists. No generated bytes are reported as originals. Measure false positives and misses per advertised capability |
| V11 | Build twice on isolated builders, verify SBOM and signatures, then try tampered or rolled back offline packages | Reproducible payloads for the claimed targets, explained signing differences, verified release provenance and SBOM. Update denies revoked signers, wrong profile, invalid signature and disallowed downgrade |
| V12 | Run end-to-end examiner workflows on all advertised systems and compare supported outputs with reference tools | Repeatable deterministic manifests and documented differences. Complete audit and report fields, accessible UI where present, and published benchmark metrics with limitations |

## Fixtures and expected baselines

- Keep small synthetic fixtures with generation seeds, source commands, exact byte ranges, expected hashes, filenames when available, acquisition expectations and a fixture license. Generate case images with contiguous files, fragmentation, partial overwrite, reused clusters, damaged metadata, dropped ranges and false magic bytes. Test stable decoding and bounded failure with images that contain nested or malicious structures.
- Use NIST CFTT imaging and carving test assertions, the CFReDS forensic images, and appropriate Digital Corpora images. Pin dataset URLs, distribution terms, original SHA-256 or verified download manifest, and expected outputs. Keep large images and case data out of the repository. Record any limitations of the ground truth.
- Compare supported methods against PhotoRec, Sleuth Kit/Autopsy and GNU ddrescue on the same fixtures where applicable. Record versions, options and reported differences. A reference tool comparison supports investigation of discrepancies. Ground truth and independent byte validation determine fixture correctness.
- Validate Android and iOS on consented test devices with known media, OS/app build numbers and controlled deletion scenarios. Preserve pre- and post-test baselines and observed side effects. Test app sandboxes, user state and documented credential paths. Keep live case evidence outside CI.
- For formal lab qualification, record procedures, equipment and calibration where applicable, environmental variables, verifier identity, uncertainty, exceptions and revalidation triggers.

[NIST CFTT Disk Imaging](https://www.nist.gov/itl/csd/secure-systems-and-applications/computer-forensics-tool-testing-program-cftt/cftt-2), [NIST CFTT Forensic File Carving](https://www.nist.gov/itl/csd/secure-systems-and-applications/computer-forensics-tool-testing-program-cftt/cftt-3), [CFReDS](https://cfreds.nist.gov/), [Digital Corpora disk images](https://digitalcorpora.org/corpora/disk-images/)

## Confidence and benchmark reporting

Record completeness independently of confidence. Begin with an ordinal rubric that records evidence strength: 0 rejected, 1 signature or metadata candidate, 2 corroborated structure with unresolved gaps, 3 structurally complete with independent validation, 4 byte-for-byte match to a trusted known hash. Keep reason codes, validator results, read-error overlap, original extents, and any generated or substituted byte ranges. A high score establishes specific validation evidence and cannot establish the identity or provenance of the original owner. Scores are ordinal, with no probability calibration implied.

Publish precision and recall separately for intact-file and partial-file detections, grouped by format, filesystem and scenario. Match intact outputs by full ground-truth hash. Match partial outputs by declared extent overlap and verified bytes under a fixed scoring procedure. Include false positives, zero-result cases, deduplication policy, throughput, peak memory, timeouts, retry counts and destination I/O. Log baseline hardware, OS, compiler, storage and dataset manifests. Establish performance targets after the initial baseline. Known-answer integrity and source write-blocking require full pass rates for supported test cases.

Use unit tests and property tests for geometry, parsing, canonicalization, bounds and ordering, with integration tests for custody and device flows. Fuzz byte and protocol parsers using `cargo-fuzz` or equivalent, in addition to runtime sandbox tests. Minimize failures into reproducible fixtures with disclosure-safe handling. Run sanitizer builds for native adapters where supported. Phase 8 requires a signed validation report and independent penetration test evidence for the declared release profiles.
