# Cross-platform product design

EaseUS demonstrates a desktop flow that starts with a location, shows scan progress, and then offers result filters and previews. Dr.Fone demonstrates a phone-oriented flow that groups findings by data type and lets the user choose what to save. These are workflow references. Their device coverage and marketing claims belong to the respective products. [EaseUS recovery guide](https://www.easeus.com/datarecoverywizardpro/), [Dr.Fone Android recovery](https://drfone.wondershare.com/android-data-recovery.html)

| Priority | Feature | OmniRecovery design |
| --- | --- | --- |
| 1 | Source and destination choice | Show storage images, approved acquisition adapters and logical exports with scope and authorization visible. On the phone, use Android's file and folder pickers and create a fresh restore folder |
| 2 | Results review and selective recovery | Filter by file type, offset, size and confidence. Add observed timestamps when the recovery engine supplies attributable time evidence. Show candidate details and later add sandboxed media previews and explicit selection for approved recovery |
| 3 | Scan progress and resume | Show observed coverage, unreadable ranges and resource limits. Resume only when the immutable source, checkpoint and recipe verify |
| 4 | Device and partition workflows | Start with image and export import. Add separately qualified partition discovery, filesystem-aware recovery and authorized USB device collection |
| 5 | Repair and transfer | Show proposed byte changes and verification level. Package existing personal files for cross-phone transfer and report verification and restoration status separately |

## Shared visual language

- Use a pale blue sidebar, white work surfaces, cobalt primary actions and mint, sky and lavender Toolbox cards. Use the platform sans-serif, visible keyboard focus, readable status text and responsive layouts. The white-ring and teal-tile icon is original OmniRecovery artwork.
- The desktop app places the result table beside a selected-finding preview and details panel. Its other workflows cover capture comparison, repair and phone transfer. The offline viewer remains available for JSON reports. Live acquisition and approved evidence recovery depend on the case-service contracts.
- Android uses the same hierarchy in a single column. The restore screen shows archive selection, destination selection, passphrase entry and verification status in order. Filesystem paths and verification states remain legible at increased text sizes.
- Use shared labels across platforms. Report evidence state with words and byte provenance so color is supplementary. Keep destructive or export actions outside the routine preview controls.
