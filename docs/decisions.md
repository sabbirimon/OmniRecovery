# Architecture decision records

The initial release target is Android evidence collection following acquisition validation. Development remains private and starts with solo synthetic testing. The high-assurance release plan includes internal validation and independent penetration testing, a deployment-specific FIPS 140-3 provider pilot, and a defined Common Criteria or procurement evaluation target. Provider, operating environment, security target and lab selection remain open.

| ID | Decision and reason | Consequence and review gate |
| --- | --- | --- |
| ADR-01 | Use a Rust workspace with an image-first CLI and local case service, with Android as the first supported device target. Rust fits the core memory-safety requirement and keeps the I/O and verification boundary independent of any UI | Pin the toolchain and dependencies. Confine `unsafe` and C FFI to reviewed adapters. Validate on synthetic images and pre/post logical exports first. Select the first qualified host OS and installable target after USB adapter tests |
| ADR-02 | Use immutable encrypted blobs plus a transactional SQLite catalogue and append-only signed ledger, scoped to each tenant | Recovery needs a documented durability model for supported storage. Advance only after injected crash, object orphan, missing object and restore tests. Keep the verifier independently deployable |
| ADR-03 | Keep privileged acquisition, trusted policy and untrusted content processing in different processes | Limit adapter access to approved handles and explicit commands. Use isolated workers for third-party parsers and decoders. Add a capability-limited WASM ABI after host sandbox and parser corpus tests pass |
| ADR-04 | Use the same typed operations for humans, deterministic runners and agent clients | Policy, audit, output filtering and effect gates live on the server. Freeze a versioned external schema after the internal jobs settle. Consider an MCP adapter over stdio after delegation and malicious input tests pass |
| ADR-05 | Use versioned crypto suites behind a provider boundary, with deployment-specific suite allowlists | The provider matrix includes certificate, security policy, runtime environment and hardware dependencies. Select a validated provider only after OS, procurement and key custody requirements are known. Reserve format fields and verifier logic for policy-driven signature migration |
| ADR-06 | Prove field-kit and lab deployment profiles independently | The field kit denies IP sockets and uses controlled media. The lab depends on TLS and tenant enforcement. Both require separate security configuration and validation evidence |
| ADR-07 | Keep evidentiary conclusions reproducible and inference advisory | Plans pin engine version, rules, options and input manifests. Replay accepted plans without a model. Models cannot write confidence scores or evidence findings. Toolchain changes require rebaselining |
| ADR-08 | Adopt per-tenant single-writer sequencing and independently held signed checkpoints | Use externally managed witness state for rollback resistance. Field deployments can use separately controlled checkpoint media. A quorum or replicated writer design requires split-brain and restore qualification |
| ADR-09 | Use Tauri for the first desktop app. Its Rust command bridge lets the UI reuse the existing engine and platform file dialogs | Build local assets and keep native file access in typed backend commands. Qualify native WebView dependencies, accessibility and OS-specific destination safeguards. Keep Qt available for reassessment if an air-gapped baseline requires a different UI runtime |
| ADR-10 | Keep media sanitization outside the recovery runtime and package it separately | Qualify device identity, destructive method, signed intent, custody retention and independent verification on sacrificial lab media before any release |

## Dependency selection

Evaluate libewf for E01/EWF, Sleuth Kit as a filesystem recovery reference and possible adapter, libimobiledevice for iOS logical workflows, and libfsapfs or equivalent for APFS research. Record the exact version, license and dependencies, attack surface, interoperability fixtures, sandbox interface and maintenance owner before adoption. Native dependencies run in isolated adapters. Freeze format behavior through fixtures and compare tool versions in reports. Do not assume source availability grants the intended distribution rights.
